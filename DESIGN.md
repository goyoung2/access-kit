# Access Kit design contract

Service administrators: preserve the immutable service owner and show a per-service administrator list with CID-based add and explicit remove confirmation. Use existing panels, tables, badges, dialogs and 44px controls. A service detail panel contains only its bound roster, member add/edit/delete/restore and file/paste import preview. Owning a site does not expose a central shared roster: an operator must explicitly delegate that source to that service; revocation and rebinding remove that delegation. Shared-roster changes explicitly apply to all consumers of that same source. Ordinary service administrators cannot see other services, change the roster binding, create services, grant platform roles, or change global membership suspension. Loading, empty, stale revision, revoked permission, deleted entry and failed import states remain visible. New navigation is `서비스 관리` for service administrators; no global user picker or other service metadata is exposed. On narrow screens the service tables scroll horizontally with a 520px minimum, preserving names, CID and role labels; mobile header actions wrap as a row. No new visual tokens.

Independent identity product. Neutral light canvas, charcoal typography, restrained indigo action. No game/alliance colors, imagery or terminology in navigation branding.

Service ownership and roster sources: distinguish platform administration from the developer role of one owned service. Developers see their own services and private rosters; shared roster choices expose names and qualification only, never the shared member export. The service form defaults to the platform's selected shared roster and allows choosing an owned private roster. Private rosters have their own lifecycle and CID rows independent of global seasons. Reuse existing panels, badges, scrollable tables, labeled fields and confirmation dialogs for create/rename/import-preview/edit/delete/restore; no new color or spacing tokens. The console adds `내 명부`, showing shared sources as read-only and private sources as editable. Empty, stale, deleted, loading, saved and permission-denied states are visible. Only the platform administrator chooses the shared default. Service-owner status never grants access to other services or central administration; global suspension remains effective.

Tokens: background #f6f7fb, surface #ffffff, text #182230, muted #667085, border #e4e7ec, primary #4657cf, danger #b42318, positive #067647. Dark login variant: background #121722, surface #1c2433, text #f4f6fb, muted #a9b4c7. System typography 14/16 body, 24/32 headings. Spacing 8/12/16/24/32; radius 12. Buttons 44px minimum. No external fonts or animations.

Console: 224px persistent sidebar and bounded content; mobile navigation horizontal, stacked controls. Pages: overview, applications, members, seasons, services, administrators, branding, history. Searchable tables with detail drawer. Action confirmation in HTML dialog, no native browser confirm. Empty, loading, failure, saved and permission-denied states visible. Persistent labels and keyboard focus.

Roster: a separate console page for records that may not yet have a Google login. Reuse console panels, search, scope filters, scrollable tables and the HTML dialog. Support individual add/edit, JSON/CSV/TSV file or pasted-table import with preview, deletion and restore. Show season, organization, UID, nickname and account-link state. Preview shows added/changed/unchanged/conflicting rows and row errors before saving; stale previews require refreshing. Deleted rows remain in a separate filter and revoke only that season membership, preserving accounts, IDs and suspension. Archived seasons are read-only. Connected UIDs are immutable in this editor; names and organization can change. Managers stay within their organization; developers have no roster access. Loading and errors stay visible inside the dialog, with keyboard focus on errors.

Login: single centered panel, service branding, Google button, application/status only. No management or SDK navigation. Console login is a separate intent and returns to console. Service branding includes title, safe HTTPS logo, accent, theme and short description, preview before save.

Member registration collects only nickname and game CID. Do not ask the member to choose a game server or affiliation. Existing account/roster namespaces are resolved by CID on the server; new CID records use the existing Korean roster default. New registrations automatically become members if the CID is in an active-season, available affiliation roster, otherwise visitors. Nickname differences do not gate registration or membership. Preserve the roster nickname and submitted nickname separately; show a discrepancy badge with the roster name only on the authorized console members table, reusing the existing badge primitive. Member/visitor/suspended filters and actions remain usable. Existing manual approvals, account IDs, suspensions and linked-CID uniqueness remain intact.

Login membership states: after Google identity is established, replace the signed-out description with identity confirmation. First registration shows an empty registration form; member registration completes immediately; visitors see completed registration and a status-refresh action without a pending-approval message. Retain pending/rejected rendering for historical applications. Suspended users see a danger-colored notice without a registration form. Members who miss a service's affiliation restriction receive a separate service-specific notice. Nickname discrepancy notices are never shown on login. Never display a permanent blanket denial alongside onboarding. Reuse existing muted/danger/positive tokens and preserve server-side membership checks.

Permission: existing operators retain superadmin authority. Scoped member managers only manage their organization; developers only own services. User identities and membership restrictions preserved. Role revocation server enforced. Last operator deletion rejected atomically.

Season and affiliation management: label the console section `시즌 · 소속`. Names are operator-defined stable identifiers; `준비 중`, `진행 중`, `종료` are separate status badges. Reuse panels, scrollable tables, filters and dialogs for create/rename/delete/restore. Keep the selected season's membership assignment below the catalog tables. Only superadmins edit catalog entries. Deletion preserves IDs and history and has a recoverable deleted-items filter; deleting an affiliation disables its seasonal access and scoped manager authority, while restore explicitly recovers those prior bindings without lifting member suspensions. An active season must be ended explicitly before deletion. Show impact counts and stale-edit errors in the dialog. Never auto-rename existing user data or choose a replacement active season on deletion.

Verification: desktop1440/mobile390, real role grant/revoke, member approval/suspension, access diagnosis, login and reconnection. Design preview uses same tokens; no mock success labels.

Developer installation: a compact service form and connection summary, followed by an optional manual-install disclosure. The document owns scrolling; no large hero or permanent step sidebar. Maximum content width1040, header64, desktop form/summary columns3:2, stacked below760. Use existing colors; title24, panel heading18, label/body14, helper12, code13; spacing8/12/16/24/32; panel radius12, field radius8, controls44 minimum. Reusable primitives: labeled field with help, service picker, policy help/lock notice, connection definition list, primary copy action, status/retry notice, manual disclosure. States cover loading, empty service list, no registered affiliations, unavailable affiliation, saved, unsaved edits, permission-locked policy and request failure. New services explicitly choose `승인된 회원`, `지정한 맹` or `최고 관리자`; explain active-season roster evaluation as supporting text. Affiliation creation remains with central administrators; existing developer-owned service policies remain locked by server rules. Show actionable reasons instead of silently disabled controls. Copy uses saved connection data, is disabled while edits are unsaved, and contains the public versioned npm guide plus non-secret connection context. Keep manual Workers/Pages/server configuration, verification and update instructions available. Desktop1440/mobile390 checks include keyboard focus, long URLs and visible primary actions.
