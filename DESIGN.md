# Access Kit design contract

Independent identity product. Neutral light canvas, charcoal typography, restrained indigo action. No game/alliance colors, imagery or terminology in navigation branding.

Tokens: background #f6f7fb, surface #ffffff, text #182230, muted #667085, border #e4e7ec, primary #4657cf, danger #b42318, positive #067647. Dark login variant: background #121722, surface #1c2433, text #f4f6fb, muted #a9b4c7. System typography 14/16 body, 24/32 headings. Spacing 8/12/16/24/32; radius 12. Buttons 44px minimum. No external fonts or animations.

Console: 224px persistent sidebar and bounded content; mobile navigation horizontal, stacked controls. Pages: overview, applications, members, seasons, services, administrators, branding, history. Searchable tables with detail drawer. Action confirmation in HTML dialog, no native browser confirm. Empty, loading, failure, saved and permission-denied states visible. Persistent labels and keyboard focus.

Roster: a separate console page for records that may not yet have a Google login. Reuse console panels, search, scope filters, scrollable tables and the HTML dialog. Support individual add/edit, JSON/CSV/TSV file or pasted-table import with preview, deletion and restore. Show season, organization, UID, nickname and account-link state. Preview shows added/changed/unchanged/conflicting rows and row errors before saving; stale previews require refreshing. Deleted rows remain in a separate filter and revoke only that season membership, preserving accounts, IDs and suspension. Archived seasons are read-only. Connected UIDs are immutable in this editor; names and organization can change. Managers stay within their organization; developers have no roster access. Loading and errors stay visible inside the dialog, with keyboard focus on errors.

Login: single centered panel, service branding, Google button, application/status only. No management or SDK navigation. Console login is a separate intent and returns to console. Service branding includes title, safe HTTPS logo, accent, theme and short description, preview before save.

Member registration collects only nickname and game CID. Do not ask the member to choose a game server or affiliation. Existing account/roster namespaces are resolved by CID on the server; new CID records use the existing Korean roster default. This internal storage key is not an applicant field or an authorization grant. The shared alliance roster and explicit administrator approval remain authoritative.

Login membership states: after Google identity is established, replace the signed-out description with identity confirmation. First registration shows an empty application form; pending shows approval status and a refresh action; rejected shows a danger-colored notice and a prefilled editable reapplication form; suspended shows a danger-colored notice without an application form. Approved members who miss a service's affiliation restriction receive a separate service-specific notice. Never display a permanent blanket denial alongside onboarding. Reuse existing muted/danger/positive tokens and preserve server-side membership checks.

Permission: existing operators retain superadmin authority. Scoped member managers only manage their organization; developers only own services. User identities and membership restrictions preserved. Role revocation server enforced. Last operator deletion rejected atomically.

Season and affiliation management: label the console section `시즌 · 소속`. Names are operator-defined stable identifiers; `준비 중`, `진행 중`, `종료` are separate status badges. Reuse panels, scrollable tables, filters and dialogs for create/rename/delete/restore. Keep the selected season's membership assignment below the catalog tables. Only superadmins edit catalog entries. Deletion preserves IDs and history and has a recoverable deleted-items filter; deleting an affiliation disables its seasonal access and scoped manager authority, while restore explicitly recovers those prior bindings without lifting member suspensions. An active season must be ended explicitly before deletion. Show impact counts and stale-edit errors in the dialog. Never auto-rename existing user data or choose a replacement active season on deletion.

Verification: desktop1440/mobile390, real role grant/revoke, member approval/suspension, access diagnosis, login and reconnection. Design preview uses same tokens; no mock success labels.
