# Access Kit

> **적용 상태 — 2026-11-17:** 0.3.1 소스에 가입 상태별 화면과 **닉네임·CID 두 항목 가입**을 반영했습니다. 11월 14일 격리된 임시 인증 서버·소비 사이트에서 설치와 가입·승인·접근 차단을 검증했습니다. 운영 서버 배포·운영 DB 변경·npm 게시는 하지 않았습니다. 공개 npm 조회는 11월 17일에도 E404이며, 아래 npm 명령은 게시 후 사용하는 예시입니다. GitHub 소스 반영은 서버 배포와 별개입니다.

코딩 LLM에게 설치를 맡기려면 [공식 설치 지시문](docs/LLM_INSTALLATION.md)을 전달하세요. 중앙 인증기의 `/guide/llm`에서도 전체 지시문을 읽을 수 있으며 설치 스튜디오는 서비스 연결 정보를 포함해 복사합니다.

같은 맹 안에서 여러 개발자가 만든 서비스가 **하나의 중앙 명부와 회원 자격**을 함께 사용하는 인증기와 SDK입니다. Google은 신원을 확인하고, Access Kit은 명부·관리자 승인·정지·소속 조건으로 입장을 판단합니다. 서비스마다 회원 명부나 Firebase 프로젝트를 복제하지 않습니다. SDK는 운영자가 지정한 인증 서버와 서비스 ID에 연결합니다.

**서비스 개발자:** 공개 npm 패키지 `@goyoung2/access-kit`를 정확한 버전으로 설치합니다. GitHub 저장소 초대는 필요 없습니다. 인증 서버의 `/guide`와 패키지 README는 로그인 없이 읽고, `/developer/install`에서 서비스 등록부터 환경별 설치 명령까지 진행합니다. 중앙 서버 서비스 등록 권한은 운영자에게 별도로 받습니다.

```sh
npm install --save-exact @goyoung2/access-kit@0.3.1
npx access-kit help
```

위 경로는 게시 준비된 설치 방식입니다. 이 소스 수정만으로 npm 게시가 이루어지지는 않습니다. 실제 게시 버전은 `npm view @goyoung2/access-kit versions --json`으로 확인합니다.

**운영자:** [서버 운영 가이드](docs/OPERATIONS.md). Firebase Google 로그인을 사용하며 회원 명부·앱·세션은 독립 DB에서 관리합니다. 기존 인증 서버·Discord에 연결하지 않습니다. 공개 SDK 배포와 회원 명부·키·운영 권한은 분리합니다.

| 구성 | 경로 |
|---|---|
| Google 로그인·닉네임/CID 가입 신청 | `/auth/firebase` |
| 관리자 로그인 | `/auth/firebase?console=1` |
| 가입 신청 승인·거절 | `/console#applications` |
| 명부 CRUD·시즌·소속·권한 관리 | `/console` (`/auth/firebase/admin`은 콘솔로 연결) |
| 개발자 서비스 등록·설치 안내 | `/developer/install` |
| 공개 설치 안내 | `/guide` — 로그인·DB 접근 없음 |
| 브라우저 SDK | `/sdk/v0.3.1/access-kit.js` (기존 v0.1.0 URL 유지) |
| 서버 SDK·설치 CLI | `@goyoung2/access-kit` — 공개 npm 배포용 패키지 |

로그인은 최초 인증부터 7일. 서비스 권한은 요청이 있을 때 최대 5분 간격으로 재확인합니다. 서비스가 거절돼도 공통 로그인은 유지됩니다. 자동 갱신 polling은 없습니다. 로그아웃하면 브라우저 쿠키를 삭제하고 중앙 토큰을 폐기하지만, 로그아웃 전에 복사한 쿠키는 다른 실행 인스턴스에서 남은 최대 5분 권한 유효기간 동안 통할 수 있습니다. 전역 즉시 폐기와는 구분합니다.

## 가입과 승인

가입자는 Google 로그인 후 **게임 닉네임과 게임 CID 두 개만** 입력합니다. 서버나 소속을 선택하지 않습니다. 화면의 CID는 기존 코드·DB의 `gameUid`/`game_uid`와 같은 식별자이며 Google UID와는 다릅니다. 기존 명부·계정·신청 기록의 연결과 삭제·정지 제한을 유지하고, 내부 키가 충돌하는 CID는 관리자 확인 전까지 차단합니다.

| 가입 상태 | 안내와 동작 |
|---|---|
| 최초 가입 | 가입 안내와 빈 신청 양식 |
| 승인 대기 | 대기 안내와 승인 상태 확인 버튼 |
| 거절 | 기존 닉네임·CID를 수정하여 재신청 |
| 정지 | 정지 안내, 가입·재신청 양식 숨김 |
| 승인 후 소속 불일치 | 가입과 구분한 해당 서비스의 소속 확인 안내 |

관리자는 `/console#applications`의 **가입 신청 → 승인 → 시즌·소속 확인 → 확인**으로 처리합니다. 명부에 CID가 있으면 그 명부의 시즌·소속이 미리 선택됩니다. 최초 최고 관리자 권한은 운영자가 확인한 계정에 별도로 지정해야 하며, 최초 로그인이나 가입 신청만으로 관리자 권한이 생기지 않습니다. 관리자 권한과 일반 회원 승인은 별개입니다.

## 임시 호스팅 검증

아래 주소는 **임시 시험 환경**이며 운영 인증 서버 주소나 공개 SDK 배포 주소가 아닙니다. 테스트용 합성 명부를 사용했고, 실제 108명 명부는 가져오지 않았습니다.

- [시험 소비 사이트](https://ak-atlas-trial-20261114.nakwol.workers.dev/)
- [시험 인증 서버 안내](https://ak-auth-trial-20261114.nakwol.workers.dev/guide)
- [시험 관리자 페이지 · 가입 신청](https://ak-auth-trial-20261114.nakwol.workers.dev/console#applications) — 지정된 관리자 계정만 접근

임시 환경의 최초 최고 관리자는 11월 14일 운영자의 명시적 확인을 거쳐 설정했습니다. 이 지정은 일반 회원 승인이나 운영 서버 권한 변경을 대신하지 않습니다.

공식 지시문과 연결 정보만 받은 새 LLM이 제공된 개발 tarball로 SDK를 설치·재배포했습니다. 이미지 36장·관측 데이터 18,000건, 약 14.8MB 페이지에서 익명 파일/API 차단, 허용 회원 입장, 실제 5분 후 명부 제외 반영, 브라우저 로그아웃을 확인했습니다. 이후 닉네임·CID 신청부터 실제 관리자 콘솔 승인, 브라우저 PKCE·SDK를 거친 사이트 입장까지 검증했습니다.

이 검사의 회원 신원은 합성 중앙 세션이며 실제 Google 계정으로 새 로그인한 전체 경로와 구분합니다. 공개 npm 설치 검증도 아닙니다. 상세 범위와 실패·보완 기록은 [호스팅 설치 시험](docs/qa/hosted-sdk-trial-20261114.md), [가입 상태별 화면](docs/qa/onboarding-ui-20261114.md), [CID 두 항목 가입·관리자 승인](docs/qa/cid-signup-20261114.md)에 있습니다.

## 무료 플랜 기준

중앙 인증 서버는 **Cloudflare Workers + D1 Free로 시작하는 구성**을 기본으로 합니다. 유료 플랜 선결제는 설치 조건이 아닙니다. 서비스 개발자는 운영자가 제공한 중앙 인증기에 연결하며 별도 명부·Firebase 프로젝트·중앙 서버를 만들지 않습니다.

| 중앙 서버 무료 한도 | 기준 |
|---|---:|
| Workers 요청 | 계정당 하루 100,000건 |
| 요청당 CPU | 10ms — DB·네트워크 대기 시간 제외 |
| D1 읽기 / 쓰기 | 하루 5,000,000행 / 100,000행 |
| D1 저장 공간 | DB당 500MB, 계정 합계 5GB |

[Workers 한도](https://developers.cloudflare.com/workers/platform/limits/) · [D1 요금](https://developers.cloudflare.com/d1/platform/pricing/) · [D1 한도](https://developers.cloudflare.com/d1/platform/limits/), 2026-11-14 확인 기준입니다. 중앙 인증 호출과 각 소비 서비스의 게이트·API·파일 요청은 구분하며, 같은 Cloudflare 계정이면 계정 한도를 공유합니다.

기기·브라우저 1개, 108명이 서비스 3개를 하루 2시간 사용하는 가정에서 로그인 부가 요청까지 넉넉히 포함한 중앙 요청 예상은 **11,664건/일**입니다. 8시간이면 **34,992건/일**입니다. 이미지 요청마다 중앙을 호출하지 않으며 사용하지 않는 동안 자동 조회도 없습니다.

관리자 조회·미리보기·가져오기를 최적화한 후 가상 108명·실제 로컬 workerd/D1의 경로별 CPU 평균은 **3.91~7.29ms**였습니다. 이는 DB emulator를 포함한 로컬 프로세스 평균입니다. [전후 수치와 검증 범위](docs/qa/admin-cpu-20261114.md)를 참고하세요.

11월 14일 실제 임시 호스팅의 tail 샘플에서는 소비 게이트 최대 **6ms**, 중앙 `/authorize` 최대 **21ms**, `/me` 최대 **13ms**가 관찰됐습니다. 중앙의 일부 요청이 10ms를 넘었으므로 **무료 플랜 CPU 기준을 전부 충족했다고 판정하지 않습니다.** 이 호스팅 시험에서 관리자 명부 경로를 다시 측정하지는 않았습니다. [실제 호스팅 측정과 한계](docs/qa/hosted-sdk-trial-20261114.md)를 참고하세요. 한도 문제가 있으면 측정·개선을 먼저 진행하며, 사용자 허가 없이 유료 전환이나 권한·세션 정책 변경을 하지 않습니다.

```sh
npm ci
npm run db:migrate:local
npm run typecheck
npm test
npm run dev
```

로컬 주소: `https://localhost:8792`. `.dev.vars.example`을 `.dev.vars`로 복사하고 Firebase 웹 앱 설정을 입력하세요. 서비스 계정 개인키는 사용하지 않습니다.

배포 상태와 검증 범위는 [검증 기록](docs/VALIDATION.md)에 명시합니다. 인증 서버의 개발자 페이지와 회원 데이터는 별도 개발자/운영자 권한이 필요합니다. 개발 저장소의 공개 여부는 npm 패키지 공개와 별개입니다. 게시 절차는 [공개 패키지 게시](docs/PUBLISHING.md)를 따릅니다.

원본에서 재사용한 구성의 출처·라이선스는 [NOTICE](NOTICE.md)에 남깁니다.

## 0.3 운영 콘솔

회원·권한·시즌·서비스·로그인 디자인은 `/console`에서 관리합니다. [운영 안내](docs/CONSOLE.md)를 참고하세요. 일반 로그인에는 관리 메뉴가 없습니다. 기존 회원 ID와 정책을 보존하는 추가 마이그레이션만 사용합니다.

`명부` 메뉴는 로그인 전 회원도 직접 추가하거나 JSON/CSV/표 붙여넣기로 가져오고, 검색·수정·삭제·복구할 수 있습니다. [명부 관리](docs/ROSTER.md)를 참고하세요. `시즌 · 소속` 메뉴에서 이름을 직접 추가·수정하고 삭제·복구합니다. 시즌 이름과 준비 중/진행 중/종료 상태를 구분하며, 삭제해도 회원 ID와 이력을 보존합니다. 서버 적용에는 `0006_catalog.sql`까지 필요하며 SDK 설치나 소스 커밋만으로 운영 DB가 변경되지는 않습니다.
