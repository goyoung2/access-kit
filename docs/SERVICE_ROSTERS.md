# 서비스별 개발자와 명부

이 문서의 공유/자체 명부는 **하나의 인증 운영 환경 내부**의 기능입니다. 창천 개발자들은 기존 창천 인증 환경의 명부를 공유합니다. 다른 맹이 자기 DB·가입자·CID 연결·상태를 소유하려면 [독립 운영 설치](INDEPENDENT_AUTH.md)를 사용합니다. 그 환경의 최고 관리자·개발자·명부·회원은 창천 환경과 분리됩니다. 중앙 DB에서 소유자만 나누는 기능을 외부 맹의 독립 운영으로 취급하지 않습니다.

작업 브랜치의 구현 기준입니다. 중앙 서버에 `0008_service_rosters.sql`과 서버 업데이트가 필요합니다. 운영/시험 서버 배포와 공개 npm 재게시를 자동으로 수행하지 않습니다.

## 역할

| 역할 | 관리 범위 |
|---|---|
| 플랫폼 최고 관리자 | 공유 명부, 공유 기본값, 개발자 등록 권한, 전체 서비스·자체 명부 |
| 서비스 개발자 | 소유한 서비스 설정과 명부 선택, 자신이 만든 명부 CRUD |
| 소속 담당 관리자 | 기존 중앙 시즌·소속 명부. 개발자 자격이 없다면 서비스·자체 명부 권한 없음 |
| 일반 사용자 | 해당 서비스의 명부에 포함된 CID로 회원 자격 판정 |

개발자 초대는 서비스 등록 자격입니다. 개별 서비스의 개발자 역할은 서버의 `application_owners`를 기준으로 하며, 다른 개발자의 서비스나 명부에 대한 권한을 주지 않습니다.

새 서비스는 플랫폼이 선택한 공유 명부를 기본으로 사용합니다. 현재 시험 환경은 기존 서비스의 시즌 정책이 창천 하나이므로 0008 적용 시 해당 공유 명부를 기본값으로 연결합니다. 기존 정책에 소속이 여러 개면 최고 관리자가 직접 선택합니다. 이름·ID를 SDK에 고정하지 않습니다.

기본값 변경은 새 서비스에만 적용합니다. 기존 서비스의 연결이나 이름·주소만 수정한 서비스의 명부는 바꾸지 않습니다. 명부가 삭제되거나 사용할 수 없으면 다른 명부로 대체하지 않고 일반 회원 입장을 차단합니다.

## 개발자 사용 순서

1. `/developer/install`에서 서비스를 등록합니다.
2. 기본 공유 명부를 사용하거나 `/console#myrosters`의 **내 명부**에서 자체 명부를 만듭니다.
3. 자체 명부는 개별 입력·닉네임/CID 수정·JSON/CSV/TSV 가져오기 미리보기·삭제·복구를 제공합니다. `members` 배열도 읽으며 파일에 없는 회원은 자동 삭제하지 않습니다.
4. 서비스의 **사용할 명부**에서 공유 명부 또는 내 명부를 선택합니다. 자체 명부 하나를 여러 소유 서비스에 연결할 수 있습니다.
5. 저장된 연결 정보로 LLM 설치 지시문을 복사합니다. 소비 사이트에는 인증 서버 주소·서비스 ID·사이트 주소를 전달하며 회원 명단을 넣지 않습니다.

공유 명부는 연결해서 원본 변경을 함께 적용받습니다. 개발자에게는 이름·상태·건수만 보여주며 공유 회원 목록의 조회·수정은 허용하지 않습니다. 자체 명부는 중앙 시즌과 독립적이고 다른 개발자의 자체 명부와 같은 CID를 넣을 수 있습니다.

Google 계정·CID 연결은 중앙에서 유지합니다. 중앙에서는 방문자인 사용자가 자체 명부에 있다면 해당 서비스의 회원으로 들어갈 수 있습니다. 그것만으로 창천이나 다른 서비스의 회원이 되지는 않습니다. 닉네임 차이는 자격 판정에 사용하지 않습니다.

## SDK 역할

중앙 `/me?client_id=...`는 해당 서비스에 한정된 `serviceDeveloper`와 `serviceRole`을 반환합니다. 소유 개발자는 자신의 명부 기반 서비스에 개발자로 접근하며, 다른 서비스에서는 그 역할이 없습니다. 기존 플랫폼 `membershipAdmin`과 구분합니다. 기존 `admin` 정책은 계속 플랫폼 최고 관리자만 허용합니다.

이 브랜치의 서버 SDK는 처리기에 `identity.serviceDeveloper`를 전달합니다. 서비스의 관리자 경로는 UI를 숨기는 것과 별도로 서버에서 검사합니다.

```js
serveAsset: (request, identity) => {
  if (new URL(request.url).pathname.startsWith('/admin/') &&
      !identity.serviceDeveloper && !identity.membershipAdmin) {
    return new Response(null, {status: 403});
  }
  return existingHandler(request, identity);
}
```

계정 비활성·전체 이용 정지·개발자 권한 회수는 서비스 소유자라는 이유로 우회하지 않습니다. 기존 7일 로그인과 요청 기반 5분 권한 확인을 유지합니다.

공개 `access-kit-sdk@0.3.1`의 기존 회원 게이트도 중앙에서 판정한 서비스별 명부 자격을 사용할 수 있습니다. 서버 처리기의 `identity.serviceDeveloper` 필드와 독립 서버 설치 도구는 공개 SDK 0.4.0부터 제공합니다.

## 보존과 마이그레이션

0008은 공유 명부 연결 메타데이터, 자체 명부·행, 서비스별 연결과 공유 기본값을 추가합니다. 기존 사용자·게임 계정·명부·시즌·정지·서비스 ID와 `approved`/`season`/`admin` 정책을 보존합니다. `roster` 정책에 연결 데이터가 없거나 자격을 확인할 수 없으면 거부합니다.

명부와 행은 삭제 상태로 보존하고 복구합니다. 중복 CID·삭제된 행·오래된 미리보기·동시 변경을 반영 전에 검사합니다. 다른 개발자의 명부 ID를 알아도 조회·편집·연결할 수 없고, 변경 트랜잭션 안에서 소유권과 개발자 상태를 다시 확인합니다.
