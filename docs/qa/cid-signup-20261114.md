# 닉네임·CID 두 항목 가입과 관리자 승인 검증

2026-11-14. 배포한 구현 commit `0a9b976e6ba11d05e639f5d72865a0d4d7693787`.

## 변경

맹 내부 서비스의 가입자는 **게임 닉네임과 CID 두 항목만** 입력합니다. 게임 서버 입력을 제거했고 신청 POST도 `nickname`, `gameUid` 두 속성만 보냅니다. 내부 API/DB의 기존 `gameUid`/`game_uid` 이름은 CID를 나타냅니다.

기존 명부·계정·가입 신청의 CID를 서버에서 대조해 내부 저장 키를 유지합니다. 새 CID는 기존 명부 가져오기의 기본값 `kr`을 사용합니다. 이 값은 신청자가 선택하는 게임 서버가 아닙니다. 이전 클라이언트가 임의의 `realm`을 보내도 입력값으로 사용하지 않습니다. 기존 기록에서 같은 CID에 여러 키가 있으면 409로 관리자 확인을 요구합니다. 명부 삭제·계정 연결·중복 승인·정지·소속 제한을 완화하거나 자동 승인하지 않았습니다.

관리 콘솔 가입 신청 표에서는 서버 표시를 제거하고 CID를 표시합니다. 승인 대화상자도 CID로 안내합니다.

## 검증

- 새 테스트 3건에서 기존 구현의 실패를 먼저 확인한 뒤 수정했습니다. 두 항목 가입·CID 정규화·클라이언트 서버 선택 무시·기존 계정 키 보존·복수 키 거부를 검사했습니다.
- 삭제된 명부의 CID도 기존 키를 유지하여 승인 시 기존 삭제 제한을 우회하지 못하는 회귀를 추가했습니다.
- 중간 구현의 전체 `npm test` 72/72와 타입 검사 통과.
- 읽기 전용 리뷰에서 기존 pending 신청 키가 누락되어 같은 CID가 다른 내부 키로 중복 승인되는 전환 결함을 실제로 재현했습니다. 이 실패를 새 회귀로 고정하고, 기존 가입 신청 기록도 대조하도록 보완했습니다. 기존 신청을 승인한 뒤 두 번째 신청이 중복 승인되지 않는 것을 확인했습니다.
- 최종 영향 검사 `login-status`·`common-membership`·`console` 15/15 및 타입 검사 통과. 재리뷰 승인.
- 로컬과 원격 Chrome 6상태에서 가입 양식의 입력이 두 개이고 `realm` 요소가 없으며, 신청 POST가 두 속성만 보내는지 확인했습니다. 신규 가입과 거절 재신청의 pending 전환, 기존 승인 대기/정지/소속 불일치 표시, 모바일 390px, JS 오류도 검사했습니다.
- 원격 실제 D1에 새 합성 신청자·명부와 담당 소속만 승인 가능한 QA 관리자를 준비했습니다. 브라우저에서 `소비 사이트 접속 → 닉네임/CID 신청 → pending → 실제 관리자 콘솔 승인 → 신청자 상태 확인 → 실제 PKCE callback → SDK 세션 → 원본 사이트` 전체 흐름 **11개 검사 통과**.
- 승인 후 원본 데이터 18,000건을 실제로 읽었고, 가져온 명부의 기존 CID 키와 신청자 내부 ID도 유지됐습니다. 승인 전 직접 데이터 접근은 401이었습니다.
- QA 관리자 권한은 검사 종료 시 그 계정의 담당 소속 행만 제거했습니다. 실제 Google 계정의 권한·가입 상태는 바꾸지 않았습니다.

브라우저 검증의 신원은 합성 중앙 세션입니다. 상태·신청·관리자 승인·PKCE·SDK·데이터 응답은 실제 호스팅 서버이며 mock하지 않았습니다. 실제 Google 계정으로 새 로그인한 검증은 아닙니다.
