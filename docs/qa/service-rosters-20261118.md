# 서비스별 개발자와 명부 검증

2026-11-18. 기준 HEAD `ede3023a4e86458d157bd590c3793684b9358a1d`, 작업 브랜치 `codex/service-roster-ownership`.

## 변경과 권한 경계

- 기존 개발자 등록 권한과 `application_owners`를 재사용해 서비스별 개발자 역할을 판정한다. 서비스 소유자는 자기 서비스의 명부와 정책을 변경한다. 다른 개발자의 서비스·자체 명부는 조회·수정·연결할 수 없다.
- 공유 명부는 중앙 원본에 연결하는 읽기 전용 선택지다. 개발자에게 회원 목록은 내보내지 않는다. 자체 명부는 소유 개발자가 생성·이름 수정·개별 입력·JSON/CSV/TSV 가져오기·수정·삭제·복구한다.
- 신규 서비스는 플랫폼의 공유 기본값을 선택한다. 기본값 변경이나 이름·주소만 변경한 저장으로 기존 연결이 바뀌지 않는다. 삭제된 명부는 일반 회원 입장을 거부하며 다른 명부로 대체하지 않는다.
- 중앙 방문자도 선택된 자체 명부의 CID와 일치하면 해당 서비스에만 회원으로 들어간다. 전체 정지·계정 비활성은 유지한다. 서비스 개발자 역할을 플랫폼 `membershipAdmin`으로 승격하지 않는다.
- 0008 마이그레이션은 기존 ID·명부·정책을 보존한다. 기존 활성 서비스의 시즌 정책에 소속 하나만 있으면 해당 공유 명부를 기본값으로 설정한다. 여러 소속이면 관리자가 선택한다.
- 기존 7일 로그인과 요청 기반 5분 권한 확인은 변경하지 않았다.

## 실제 브라우저 검증

로컬 Hono+Miniflare 서버 `127.0.0.1:9084`에서 합성 Google 세션·개발자 Alice/Bob과 합성 명부를 사용했다. 실제 Google 로그인이나 원격 시험 DB 변경은 수행하지 않았다.

1. Alice 화면에 공유 명부 메타데이터와 자기 명부만 표시되고 Bob 명부가 나타나지 않았다.
2. 자체 명부 생성 → `members` JSON 2명 미리보기 → 가져오기 → 닉네임 수정 → 행 삭제 → 삭제 목록에서 복구를 실행했다.
3. 설치 화면의 초기 공유 기본값을 자체 명부로 바꿔 서비스를 저장했다. 저장 후 설정을 다시 수정할 수 있고 설치 지시문 복사가 활성화됐다.
4. 복사한 지시문에 인증 서버·서비스 ID·사이트 주소·회원 정책만 포함되고 합성 명부 CID가 포함되지 않음을 확인했다.
5. Bob으로 전환한 화면에서 Bob 명부만 표시되는 것을 확인했다.
6. 설치 화면은 CSS viewport 폭 355px에서 가로 넘침 없이 명부를 선택할 수 있었다. 자체 명부 화면의 모바일 viewport 변경은 적용이 확인되지 않아 해당 화면의 모바일 검증으로 계산하지 않았다. 자체 명부 화면은 데스크톱에서 확인했다.

스크린샷: 로컬 ignored 경로 `private-roster-desktop.jpg`, `installer-private-roster.jpg`. `private-roster-mobile.jpg`는 viewport 적용 증거가 아니므로 모바일 검증 자료로 사용하지 않는다. 마지막 테스트 이후 추가한 CID 정규화·기본값 보존·메타데이터 보완은 자동 테스트로 확인했다.
