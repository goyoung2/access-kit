# CID 명부 기반 자동 가입 검증 — 2026-11-18

## 결과와 범위

새 가입은 Google 로그인 이후 닉네임·CID만 받는다. 진행 중인 시즌의 등록된 소속에 유효한 명부 CID가 있으면 맹원, 없으면 방문자로 완료된다. 닉네임 차이는 자격을 막지 않으며 관리자 회원 표에만 확인 표시를 제공한다. 운영/시험 서버 배포, 원격 DB 변경, GitHub push, npm 게시는 수행하지 않았다.

원본 수집 JSON의 `members` 배열을 지원한다. 사용자가 제공한 실제 파일은 메모리에서 파싱해 **200명 / 오류 0 / 중복 CID 0**을 확인했다. 실명부·개인 닉네임·CID를 저장소나 원격 DB에 넣지 않았다. 브라우저와 DB 검증은 합성 데이터로 수행했다.

## 구현

- `0007_automatic_registration.sql`은 자동 가입 및 입력 닉네임을 별도 테이블에 저장한다. 기존 ID·수동 승인·정지를 변경하지 않는다.
- 가입과 CID 연결, 동시 요청 검사, 이력 기록은 같은 D1 트랜잭션으로 처리한다. 이미 연결된 CID나 가입 뒤 CID 변경은 409로 거부한다.
- 맹원 상태와 서비스 접근은 유효한 명부를 조회해 판정한다. 명부 추가·삭제·복구, 시즌 전환, 소속 삭제가 자동 가입자의 자격에 반영된다. 정지는 이 판정보다 우선하며 명부 복구로 풀리지 않는다.
- 가입 닉네임은 별도 보존한다. 기존 명부 동기화 트리거에 가입 닉네임이 유입되지 않도록 게임 계정에는 명부의 기준 닉네임을 보관한다. 소속 재등록으로도 명부 이름을 덮어쓰지 않는다.
- 관리자 표는 가입 닉네임·명부 닉네임·불일치 표시 및 맹원/방문자/정지 필터를 제공한다. 담당 맹 관리자만 해당 회원의 확인 정보를 볼 수 있으며 개발자·일반 회원은 볼 수 없다.
- 과거 대기 신청의 승인/연결과 기존 수동 승인 정책은 유지한다. 신규 자동 가입에는 승인 대기 단계가 없다.

## 실행한 검증

1. 전체 `npm test`: **83/83 통과**. 이후 발견한 자동 가입자의 소속 관리 연결을 보완하고 확인 테스트 2개를 추가했다.
2. 최종 영향 범위: `automatic-registration`, `common-membership`, `catalog`, `console` 테스트 **28/28 통과**. CID 중복·동시 가입, 맹원/방문자, 관리자 범위, 닉네임 일치/불일치, 명부 CRUD, 정지/해제, 시즌/소속 상태, 카탈로그 영향 건수, 기존 수동 승인 경로를 검증했다.
3. 실제 PKCE 코드 발급·교환 후 접근을 확인했다. 명부에서 제외하면 이미 발급된 토큰도 중앙 권한 검사에서 거부되고 방문자에게 새 코드를 발급하지 않는다. SDK의 기존 요청 기반 권한 확인 주기(최대 5분)는 유지한다.
4. `npm run typecheck` 통과. Wrangler 로컬 dry run 통과; 실제 업로드/배포는 하지 않았다.
5. 실제 Hono 라우트와 로컬 Miniflare D1을 연결한 브라우저에서 다음을 조작했다.
   - 명부와 다른 닉네임으로 맹원 즉시 가입: 완료 상태, 가입 폼 숨김, 사용자용 불일치 안내 없음.
   - 명부에 없는 CID: 방문자 가입 완료, 승인 대기 안내 없음.
   - 관리자 회원 표: 두 닉네임 및 확인 표시, 방문자 필터.
   - 관리자 정지/해제: 해당 사용자의 정지 화면 및 맹원 상태 복구.
   - 390×844 방문자 화면: 가로 넘침 없음.

Google 신원 단계는 합성 로그인 세션을 사용했다. Firebase 초기화 모듈만 로컬 대체했고, 가입·상태·관리자·DB·서비스 권한 처리는 실제 코드를 사용했다. 새로운 실제 Google 팝업 로그인이나 원격 호스팅 검증은 하지 않았다.

검증 로그·로컬 하네스·합성 화면 캡처는 Git 제외 경로 `.wrangler/roster-registration-qa-20261118/`에 보관한다. 도입 시 중앙 서버 DB에 0007 마이그레이션과 서버 코드 반영이 필요하며 SDK 설치만으로 적용되지 않는다.
