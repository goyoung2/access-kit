## 중간 실패와 검증 한계

- 이전 미게시 이름 `@goyoung2/access-kit`의 게시 요청은 404로 실패했습니다. 일반 패키지명으로 코드·생성 템플릿·업데이트·문서를 함께 정정했습니다. 실패한 이름으로 게시에 성공했다고 보고하지 않습니다. 기존 로컬 `v0.3.1` 태그는 이동하지 않았고 새 게시 태그를 사용했습니다.
- npm은 요청 수락 직후 임시 `0.0.0-stage` 버전을 표시했고 CDN도 잠시 404를 반환했습니다. 실제 `0.3.1` 다운로드와 안내 문서의 200을 확인한 후 설치 시험을 진행했습니다.
- 최초 CLI의 Windows 격리 환경에서는 설치와 doctor 이후 esbuild 하위 프로세스가 `spawn EPERM`으로 차단돼 전체 D1 검증이 끝나지 않았습니다. 이 시도를 완전 통과로 취급하지 않았습니다. 검증 도구와 테스트 조건은 유지하고, 별도 깨끗한 프로젝트의 새 에이전트로 다시 설치·검증했습니다.
- 이번 검증은 **로컬 합성 계정** 기준입니다. 실제 Google 로그인, 새 원격 호스팅과 운영 서비스 보호 검증은 수행하지 않았습니다. 기존 임시 호스팅 시험과 그 CPU·로그아웃 한계는 [이전 보고서](hosted-sdk-trial-20261114.md)를 유지합니다.
- 서버를 배포하지 않았으므로 기존 중앙 서버의 내장 안내에는 이전 패키지명이 남을 수 있습니다. 배포 없이 읽을 수 있는 위 공개 npm 문서가 이번 SDK 설치 안내입니다.
