## 공개 패키지로 설치한 가상 사이트

가상 운영 대시보드에 4,000건의 합성 업무 자료, 그래프, 검색, 다운로드와 API를 만들었습니다. 사이트 프로젝트에서 빈 npm 사용자 설정으로 공개 레지스트리의 정확한 `0.5.0`을 설치하고 빌드 → SDK `init` 계획 확인·적용 → `doctor` → 세션 비밀키 설정 → 배포를 실행했습니다. 로컬 tarball로 대체하지 않았습니다.

기존 Worker 핸들러·바인딩을 유지하고 `run_worker_first`로 HTML·JS·CSS·JSON·SVG·다운로드·API를 게이트 뒤에 두었습니다. `doctor`의 생성 파일, 설정, 게이트, 빌드 결과, 보호 경로 검사가 모두 통과했습니다. Worker 세션 키는 출력하거나 Git에 저장하지 않았습니다.

[공유 설치 안내](https://unpkg.com/access-kit-sdk@0.5.0/docs/LLM_INSTALLATION.md)와 [독립 운영 안내](https://unpkg.com/access-kit-sdk@0.5.0/docs/LLM_INDEPENDENT.md)가 공개 HTTP 200으로 제공되는 것을 확인했습니다. 이번 원격 설치는 안내에 따른 실행 검증이며, 새 LLM 세션에 지시문만 전달하는 별도 블라인드 시험은 이번에 반복하지 않았습니다. 이전 지시문 설치 시험은 [기존 기록](npm-short-prompt-20261117.md)에 구분해 남겨 둡니다.

## 공동 관리자와 명부 관리

실제 최고 관리자 로그인 세션으로 시험 서비스 A와 별도 격리 서비스 B, 각 서비스의 전용 시험 명부를 만들었습니다. 합성 계정 5개에는 실제 Google 사용자 신원을 만들지 않고 시험용 서버 세션만 부여했습니다. 가입은 실제 `/auth/firebase/apply` 요청을 사용했고, 창천 CID가 아닌 계정들은 공통 가입 분류가 방문자인 것을 확인했습니다.

브라우저에서 실제 콘솔을 조작해 다음을 확인했습니다.

1. 서비스 소유자가 첫 공동 관리자를 추가했습니다.
2. 첫 공동 관리자가 두 번째 공동 관리자를 추가해 소유자 포함 3명이 되었습니다.
3. 공동 관리자가 A의 전용 명부에서 항목 추가·닉네임 수정·삭제·복원을 수행하고, JSON 두 항목을 미리보기 후 가져왔습니다.
4. 두 번째 공동 관리자가 첫 공동 관리자를 해제했습니다.
5. 해제된 계정의 콘솔 새로고침과 호스팅 사이트 재접속은 403이 되었습니다.

공동 관리자 화면에는 배정된 A만 보였습니다. B 조회·관리자 추가·명부 변경·설정 변경, 중앙 관리자 승격·전역 회원 정지는 403이었습니다. B 자신의 명부 회원은 B 인증 코드를 받을 수 있었으므로 다른 서비스를 일괄 차단하는 방식으로 격리를 대신하지 않았습니다.

| 실제 5분 경과·로그아웃 | 3 | 권한 해제 전 쿠키로 자료 접근 403, 회원 로그아웃 204, 로그아웃한 중앙 토큰 401 |

해제 직후 기존 사이트 쿠키는 200이었고, 실제 5분 권한 재확인 시점을 지난 뒤 같은 쿠키는 403이었습니다. 시간을 조작하지 않았습니다. 사이트의 7일 로그인 세션과 요청 시 5분 권한 재확인 정책을 유지했습니다.

마지막에는 기존 실제 Google 로그인 계정의 세션으로 새 사이트에 입장했습니다. `입장 확인 완료 · 이 서비스의 관리자`, API 200, 자료 4,000건, 기본 표시 300행, 검색 시 1행과 초기화 후 300행을 브라우저에서 확인했습니다. 이 확인은 기존 Google 로그인 세션의 재접속이며, 새 Google 계정 가입이나 새 로그인 팝업 시험으로 계산하지 않았습니다.

로컬 소스 검증은 테스트 107개 통과·타입 검사 통과입니다. [개인정보 없는 검증 영수증](coadmin-rollout-20261123.json)에 원격 검사별 결과를 보관합니다.

## 정리와 데이터 보존

검증 후 합성 계정 5개, 임시 서비스 B, 임시 전용 명부 2개와 시험 공동 관리자 지정을 제거했습니다. 실제 사람에게 관리 권한을 부여한 상태로 남겨 두지 않았습니다. 새 사이트 A는 남겨 두고 **기존 창천 공유 명부**에 연결했습니다. 창천 원본 항목은 변경하지 않았습니다.

기존 회원 ID·가입·CID 연결·제한·역할·서비스·명부 연결 등의 원본 행을 배포 전 사본과 대조해 모두 보존된 것을 확인했습니다. 창천 명부는 198명이며 전체 행 SHA256은 배포 전후 동일한 `8b1a127553f6aef89aa3915aebddbb0e6ab8b4deedb1953ca6a63d91b40ae749`입니다. 기존 다른 Worker의 ETag·변경 시각과 Pages 배포 ID도 동일했습니다. D1 백업과 세션·회원 원본은 로컬 비공개 작업 폴더에만 보관했습니다.

시험 과정에서 npm CDN의 일시적인 404는 공개 전파 후 정상 다운로드됐습니다. 브라우저 데이터 갱신 대기와 시험 스크립트의 import 진입점 문제는 시험 도구에서 수정한 뒤 재실행했습니다. 이 기록은 CPU 부하 한도·다른 브라우저의 신규 Google 가입·독립 인증 서버 신규 배포를 검증한 결과로 확대하지 않습니다.
