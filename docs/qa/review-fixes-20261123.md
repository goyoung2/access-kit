# 0.6.1 검토 발견 3건 수정과 검증

검증일: 2026-11-23 KST. 수정·서버 릴리스 소스: `71dceccdc6fee78ab9bc75eab4a0fc8ac9062d2a`.

## 수정한 동작

1. **구형 개발자 초대의 권한 재검사**: 구형 초대 수락도 발급자가 현재 활성 최고 관리자인지, 수신자가 활성·비정지 계정인지 초대 소비와 같은 D1 트랜잭션에서 확인합니다. 발급자 권한이 쓰기 직전에 회수되는 경합도 차단합니다. 정상 초대와 1회 사용 제한은 유지합니다.
2. **기존 회원에 Google 계정 연결 시 권한 보존**: 기존 회원 ID에 Google 로그인을 연결할 때 서비스 소유권, 자체 명부 소유권, 서비스 공동 관리자 지정과 유효한 미수락 초대 발급 권한을 함께 옮깁니다. 같은 공동 관리자 지정은 합치고, 소유자에게 중복 공동 관리자 행을 만들지 않습니다. 명부·서비스 ID와 처리된 초대의 과거 발급자 기록을 유지합니다. 원본 또는 대상 계정의 명시적인 서비스 등록 권한 회수는 해제하지 않습니다.
3. **오래된 초대 조회·취소**: 기록 삭제 없이 생성 시각·ID 커서로 100건씩 조회합니다. **더 불러오기**로 이전 미사용 초대까지 찾아 취소할 수 있습니다. 같은 생성 시각과 조회 도중 새 기록이 들어오는 경우에도 페이지 중복·누락을 막습니다. 다른 서비스의 커서를 넣어도 권한을 얻지 못합니다. 대화상자 안 취소 버튼의 클릭 처리 누락도 고쳤습니다.

`0011_permission_reservation_pagination.sql`은 조회 인덱스 두 개만 추가합니다. 배포 시 기존 회원·명부·권한 행을 변경하는 데이터 마이그레이션은 없습니다. 계정 연결의 권한 이전은 앞으로 관리자가 해당 연결 승인을 실제 실행할 때만 적용됩니다.

## 실제 Cloudflare 기능 검증

기존 사용자와 창천 CID를 쓰지 않고 새 시험 Worker·DB에 합성 계정과 명부를 구성했습니다. 실제 HTTP API로 **27/27** 검사를 통과했습니다.

- 관리자 회수 뒤 구형 초대 수락 409·서비스 생성 403. 정상 초대 200·재사용 409.
- 기존 회원 연결 승인 200. Google 신원은 기존 회원 ID에 연결되고, 소유 서비스·같은 자체 명부·다른 서비스의 공동 관리자 권한은 계속 200입니다. 원래 가입 계정의 세션은 무효화됐습니다.
- 연결 전 발급한 미수락 초대도 연결 후 정상 수락되며, 그 초대로 다른 서비스 권한을 얻지는 못합니다.
- 첫 페이지는 100건이며 다음 커서로 더 오래된 대기 초대가 나타납니다. 중복 없는 마지막 페이지와 잘못된 커서 400, 다른 서비스 조회 403을 확인했습니다.

브라우저에서 첫 **100건 → 102건**을 불러오고 오래된 대기 초대의 **예약 취소 → 확인 → 재조회**까지 실행했습니다. 이후 대기 0건·취소 101건·수락 이력 1건이었습니다. 390px 화면에서도 페이지 넘침 없이 대화상자가 표시됐습니다. 처음에는 취소 버튼 이벤트가 본문에만 연결돼 요청이 나가지 않는 결함을 확인했고, 대화상자에 취소 이벤트를 연결한 뒤 같은 절차를 통과했습니다.

시험 Worker·DB는 검증 후 이 작업에서 만든 리소스만 삭제했습니다. 이 시험은 합성 Firebase 종류 세션과 합성 신원 레코드를 사용했으며 실제 Google 신규 로그인으로 계산하지 않습니다.
