# 서비스 공동 관리자 검증

2026-11-23 KST. 기능 기준 커밋 `3b14a13c925b501b7793c2c9f45867bdf4b2e35b`. 이전 운영·게시 기준은 `724cfd18666c16421bc75be9c34f0ba3f1b02cf4`. 소스 개발본이며 이번 작업에서는 원격 서버·DB·GitHub·npm에 쓰기 작업을 하지 않았다.

## 동작

마이그레이션 0009는 기존 소유자·회원·명부를 보존하고 서비스별 공동 관리자 및 명부 위임 테이블을 추가한다. 기존 소유자는 해제할 수 없고, 활성 공동 관리자는 해당 서비스에 한해 관리자 추가·해제, 이름·URL·로그인 디자인, 위임된 연결 명부의 회원 CRUD·파일 가져오기를 수행한다. 연결 명부와 입장 정책 변경은 소유자·중앙 관리자에게 남긴다.

서비스 생성 권한이나 중앙 역할은 공동 관리자 지정으로 부여하지 않는다. 자체 명부는 서비스 소유자의 자원일 때 공동 관리하며, 중앙 공유 명부와 다른 소유자의 원본은 중앙 관리자의 명시적 서비스 위임이 필요하다. 일반 서비스 등록만으로 공유 명단이 노출되지 않는다. 원본을 공유하는 서비스는 명부 변경을 함께 적용받지만 다른 서비스 설정·관리자 권한은 부여되지 않는다. 연결 변경·해제는 이전 위임을 지운다.

## 자동 검증

- 전체 테스트 **107/107** 통과. 기존 인증·회원 상태·명부 CRUD·SDK 게이트·7일 세션/5분 lease·설치/복구/배포 fixture를 포함한다.
- 마지막 설치 스튜디오 수정 후 관련 **14/14**를 다시 확인했다. 이 14개는 전체 107개에 포함된 서비스/명부 범위다.
- 새 권한 테스트 5개는 실제 로컬 D1과 Hono API를 사용한다. 3인 관리, 소유자 해제 거부, 다른 서비스의 읽기·관리자 지정·명부·디자인·설정 차단, 글로벌 역할·정지 우회 차단을 확인한다. CID로 관리자 추가는 아래 브라우저 조작으로도 확인했다.
- 실제 DB batch 직전에 관리자를 해제하거나 공유 원본 위임을 회수하는 경합을 주입했다. 저장은 409로 거부되고 명부 행은 생성되지 않았다. 서비스 재연결 후 위임이 남지 않는 것도 확인했다.
- 자체 명부의 가져오기·행 revision·stale 요청·삭제/복구를 보존했다. 개발자이면서 다른 서비스의 공동 관리자인 계정도 서비스별 정책 변경 가능 여부와 명부 선택 정보가 분리된다.
- `npm run typecheck` 통과. 패키지 검사는 허용 파일 경로·template manifest 해시·마이그레이션 0009·공동 관리자 안내 포함과 실제 tarball 설치/doctor를 확인한다. 이 tarball은 미게시 로컬 개발본이며 공개 0.4.0과 다르다.

## 실제 브라우저

Playwright DOM 조작으로 로컬 HTTP 서버 → 실제 Hono → Miniflare D1을 연결했다. 신원은 명시적으로 합성 Firebase-kind 세션을 사용했으며 실제 Google 로그인 시험으로 계산하지 않는다.

1. 소유자가 CID 2001, 2002로 공동 관리자를 추가해 관리자 3명을 확인했다.
2. 별도 브라우저 컨텍스트의 공동 관리자가 같은 명부의 회원을 추가·수정·삭제·복구했다.
3. 실제 파일 선택기로 JSON 2명을 가져와 미리보기·확인 저장 후 기존 1명과 합계 3명을 확인했다.
4. 담당 서비스는 200, 다른 서비스는 403이며 콘솔 목록에는 담당 서비스만 표시됐다.
5. 소유자가 관리자 해제를 실행하자 기존 세션의 콘솔/API가 403이 됐고 화면의 명부 내용도 재조회 시 제거됐다.
6. 공유 원본은 위임 전 행 0·편집 불가, 중앙 관리자의 콘솔 위임 후 공동 관리자 쓰기 성공, 콘솔 회수 후 다시 행 0·편집 버튼 0을 확인했다.
7. 잘못된 JSON은 실제 오류 문장을 표시하고 저장 버튼을 노출하지 않았다.
8. 데스크톱 1440 및 모바일 390에서 확인했다. 모바일 document width 375, 표 내부 scroll width 520, 버튼 높이 최소 44px. 좁은 표의 이름·CID·역할 글자 줄바꿈 문제를 실제 캡처에서 확인해 표 내부 스크롤로 수정했다.

근거: [브라우저 검사 결과](service-administrators-20261123/browser-proof.json). 전체 로그·합성 DB·스크린샷은 ignored `.wrangler/service-coadmins/`에 보존한다.

## 발견한 문제와 수정

서비스 관리자 SQL view를 기존 중첩 JSON snapshot에 직접 넣었을 때 D1이 `VIEWs and/or subqueries nested too deep`로 실패했다. 해당 사용자의 작은 서비스 ID 집합을 별도 고정 쿼리로 얻어 JSON CTE에 전달하도록 바꿔 콘솔 503을 해결했다. 권한을 없애거나 오류 응답을 성공으로 처리하지 않았다.

설치 스튜디오는 공동 관리자가 소유하지 않은 연결 명부의 메타데이터도 자기 서비스 범위 안에서 제공한다. 전역 개발자 권한이 있는 공동 관리자도 다른 소유자의 서비스 정책을 변경하지 못하도록 서비스별 `canChangePolicy`로 잠금 상태를 결정한다.

설치 지시문의 반복적인 배포 허락 요구와 설치 스튜디오의 강제 `deploymentAllowed:false`를 제거했다. 이미 받은 설치·배포 지시는 다시 묻지 않으며 실제 사용자의 배포 금지·요청 범위는 유지한다. 생성된 서버 내장 지시문도 같은 원문에서 갱신했다.

## 적용 범위

이번 결과는 로컬 소스·패키지·브라우저 검증이다. 기존 창천 198명 운영 명부, 배포 서버, 공개 npm 패키지는 변경하지 않았다. 운영 적용에는 0009와 인증 서버 갱신이 필요하고, 고정된 공개 npm 0.4.0 문서는 새 버전 게시 전에는 바뀌지 않는다.
