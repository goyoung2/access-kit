# 회원의 서비스 자동 등록과 가입 전 권한 예약 · 0.6.0

검증일: 2026-11-23 KST. 소스·npm 릴리스 커밋: `fa2681ec6f4fe91eae652568f07c34a7c8620933`.

## 바뀐 사용 흐름

창천 기본 명부에 CID가 있는 가입자는 별도 개발자 승인 없이 [설치 스튜디오](https://access-kit.nslg-hub.workers.dev/developer/install)에서 자기 서비스를 등록합니다. 등록한 계정은 해당 서비스의 소유자로 공동 관리자를 추가·해제할 수 있습니다. 기본 명부의 현재 자격을 등록 시점과 쓰기 트랜잭션 안에서 재검사합니다. 방문자·정지 계정·삭제된 명부 자격·명시적으로 서비스 등록 권한이 회수된 계정은 자동 등록할 수 없습니다.

새 서비스 등록 자격과 이미 소유한 서비스의 관리 권한은 구분합니다. 명부에서 빠지면 새 서비스 자동 등록은 중지되지만 기존 소유권은 삭제하지 않습니다. 계정 정지·명시적인 등록 권한 회수는 기존 권한 경계에 따라 서버에서 적용합니다. 공유 명부 회원 목록과 수정 권한은 자동으로 주어지지 않고 중앙 최고 관리자의 서비스별 위임으로만 열립니다.

가입 전 권한 지정은 [관리자 · 권한](https://access-kit.nslg-hub.workers.dev/console#roles) → **가입 전 권한 예약**입니다. CID와 역할·담당 범위를 정하고 생성된 일회용 링크를 전달합니다. 서비스 관리자는 해당 서비스의 **가입 전 관리자 예약**에서 그 서비스의 공동 관리자만 예약할 수 있습니다. 수신자는 Google 로그인·닉네임/CID 가입을 마친 뒤 링크를 수락합니다. CID 입력만으로는 관리 권한이 부여되지 않습니다. 링크는 7일·1회용이며 DB에는 해시만 저장합니다. 다른 CID·취소·만료·중복 수락과 초대한 관리자의 권한 회수는 차단합니다.

## 로컬 검증

- 전체 테스트 **113/113**, 타입 검사 통과.
- 마지막 초대 범위 표시·설치 안내 변경 후 관련 테스트 **11/11** 재검증.
- 신규 회귀 테스트는 회원 자동 등록, 공유 명부 위임·회수, 방문자·정지·명시적 회수, 가입 전 예약과 명시적 수락, 전역 역할 예약, 잘못된 CID·중복·만료·취소·다른 Origin, 초대한 관리자의 권한 회수, 서비스 생성 중 회원 자격 변경에 대한 원자적 취소를 다룹니다.
- 기존 관리자 명부 조회·가져오기와 제한된 D1 호출 수 검사도 전체 회귀에 포함했습니다.

초기 시험 중 로컬 D1 통신의 `fetch failed`가 한 번 발생해 로그를 보존했습니다. 해당 시험을 단독 재현한 뒤 관련 11개 및 전체 회귀를 통과했습니다. 또한 최고 관리자의 콘솔 역할 표시가 기존과 달라진 회귀를 확인해 기존 표시를 유지하도록 수정한 뒤 전체 113개를 다시 통과했습니다. 실패를 제외해 통과 개수를 만든 것이 아닙니다.

## 분리된 Cloudflare 환경: 31/31

창천 원본과 CID 연결을 건드리지 않도록 새 시험 Worker·D1에 합성 명부·세션을 만들었습니다. 실제 HTTP 경로로 다음을 검증했습니다.

- 명부 회원은 `developers` 테이블의 부여 행 없이 설치 스튜디오·콘솔에 들어가 자기 서비스를 등록합니다.
- 방문자의 새 서비스 생성은 403이며, 소유자가 추가한 공동 관리자는 배정 서비스만 관리합니다.
- 공동 관리자의 다른 서비스 접근과 전역 권한 예약은 403입니다.
- 공유 원본은 위임 전 숨겨지고 최고 관리자 위임 후에만 보이며, 회수하면 다시 숨겨집니다. 서비스 소유자는 스스로 위임할 수 없습니다.
- 가입 전 CID 예약 → 가입만으로는 권한 없음 → 링크 수락 → 배정 서비스 관리 → 권한 해제 후 403을 확인했습니다.
- 잘못된 CID·재사용·예약 취소·명시적 등록 권한 회수를 차단했습니다.

실제 브라우저에서도 개발자 부여가 없는 합성 명부 회원이 설치 스튜디오에서 서비스를 등록하고 가입 전 공동 관리자 예약 링크를 생성했습니다. 생성한 링크는 확인 버튼 처리 후에도 화면에 남아 복사할 수 있었습니다. 시험 Worker와 DB는 검증 후 이 작업에서 생성한 리소스만 삭제했습니다.

이 환경의 계정은 합성 서버 세션이며 새 Google 로그인 성공으로 계산하지 않았습니다. 실제 창천 CID를 임시 계정에 연결하거나 창천 기본값·명부 행을 바꾸어 시험하지 않았습니다.

## 새 창천 서버의 실제 브라우저 검증

새 서버에 `0010_member_services_and_reservations.sql`과 0.6.0을 반영했습니다. D1 백업을 먼저 저장했습니다. 기존 최고 관리자의 실제 로그인 세션으로 콘솔을 열고, 아직 존재하지 않는 시험 계정의 CID에 **서비스 공동 관리자**를 예약했습니다.

이후 별도의 합성 수신자 세션으로 실제 가입 화면에서 닉네임·CID를 입력했습니다. 방문자로 가입되었고 수락 전 콘솔은 403이었습니다. 초대 화면에서 링크를 수락하자 콘솔은 200, 배정 서비스는 1개, 최고 관리자 권한은 false, 공유 명부 목록은 0개였습니다. 기존 호스팅 시험 사이트에 들어가 `입장 확인 완료 · 이 서비스의 관리자`, 자료 4,000건과 API 200을 확인했습니다.

실제 최고 관리자가 해당 권한을 해제한 뒤 콘솔·원래 담당 서비스·다른 서비스 요청 모두 403이었습니다. 시험 계정과 이번에 만든 예약은 삭제했습니다. 기존 사람에게 추가 권한을 남기지 않았습니다. 이 검증의 수신자는 합성 세션이며 새로운 Google 사용자 신원을 만들지 않았습니다. 기존 실제 Google 로그인 세션은 최고 관리자 조작에만 사용했습니다.
