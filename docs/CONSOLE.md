# Access Kit 0.3 운영 콘솔

관리 주소: `/console`. 일반 서비스 로그인에는 관리 링크가 없습니다. 콘솔에 직접 접속하면 별도 관리자 로그인 의도로 인증합니다.

## 명부 입력·수정·삭제

`명부` 메뉴(`/console#roster`)에서 Google 로그인 전인 사람도 등록합니다. 한 명 추가, JSON/CSV/표 붙여넣기 미리보기, 검색·필터, 수정, 삭제·복구를 제공합니다. CID는 게임 UID로 사용합니다. 삭제는 해당 시즌 소속 해제이며 계정·회원 ID·전체 정지를 삭제하지 않습니다. 담당 조직 권한과 동시 수정 검사를 서버에서 적용합니다. 자세한 형식·사용 순서는 [명부 관리](ROSTER.md)를 참고하세요. 중앙 서버에는 `0005_roster.sql`이 필요합니다.

## 역할

- 최고 관리자: 회원·시즌·서비스 정책·디자인·권한 관리. 기존 auth_operators 계정은 그대로 최고 관리자입니다.
- 회원 관리자: 지정한 맹의 신규 신청 승인 및 소속 등록·해제. 다른 맹 이동, 기존 계정 연결, 전체 회원 정지, 서비스 정책 변경, 권한 위임은 할 수 없습니다. 다른 맹에 영향을 주는 전체 정지/거절은 최고 관리자가 처리합니다.
- 개발자: 본인이 등록한 서비스 연결·디자인 관리. 회원 자격은 별도입니다.
- 일반 회원: 본인 가입 신청과 승인 상태 확인, 서비스의 기존 회원/시즌 조건을 만족할 때 입장합니다.

`관리자 · 권한`에서 계정을 검색하고 `권한 설정`을 누릅니다. 역할, 담당 맹(회원 관리자), 부여/회수를 선택합니다. 자신의 최고 관리자 권한은 다른 최고 관리자가 회수합니다. 마지막 최고 관리자 삭제는 DB 제약으로도 막습니다. 아직 계정이 없다면 대상자가 먼저 Google 로그인을 합니다. 개발자는 7일·1회용 초대 링크도 사용할 수 있습니다.

## 회원 업무

`가입 신청`에서 닉네임·서버·UID 및 중복 표시를 확인하고 시즌·맹을 지정해 승인합니다. 기존 회원 연결은 고급 항목의 회원 선택을 사용합니다. 내부 ID 입력은 필요 없습니다.

`회원`에서 이름/UID 검색, 승인/정지 필터, 개별 또는 선택 회원 정지·해제를 합니다. `접근 확인`은 각 서비스의 실제 서버 정책을 조회해 접근 가능/정지/시즌 소속 불일치를 표시합니다. 일괄 작업은 처리된 수를 표시하며 실패한 나머지를 성공으로 표시하지 않습니다.

`시즌 · 맹`은 기존 시즌 이력을 보존합니다. 다음 시즌 복사 시 이미 설정된 등록/해제 상태를 덮어쓰지 않습니다.

`연결 서비스`에서 승인 회원 전체/현재 시즌 지정 맹/최고 관리자 전용 정책을 선택합니다. 회원 관리자를 최고 관리자 전용 서비스에 자동 입장시키지 않습니다.

## 로그인 디자인

`로그인 디자인`에서 서비스 이름·안내·HTTPS 로고 URL·강조색·밝은/어두운 테마를 설정하고 미리 봅니다. 등록된 서비스의 인증 요청에만 해당 디자인을 적용합니다. 기본 콘솔은 중립적인 밝은 디자인입니다. 관리자와 SDK 메뉴는 일반 로그인 화면에 없습니다.

SDK0.3은 최초 비로그인 접속에서 중앙 Google 로그인 화면으로 바로 연결합니다. Google 버튼을 두 번 누르는 기존 동선을 없앴습니다. 기존0.2 SDK도 중앙 인증과 계속 호환됩니다.

## 적용 및 유지

마이그레이션 `0003_console.sql`은 member_managers, login_branding 및 마지막 관리자 보호 트리거만 추가합니다. 기존 회원·식별자·명부·정책을 변환하거나 삭제하지 않습니다. 먼저 DB 백업 후 적용하고 인증기를 배포합니다. SDK0.3 교체는 각 서비스에서 별도로 진행합니다.

관리 권한 회수는 다음 콘솔 요청부터 적용됩니다. 회원 정지·시즌 변경은 기존 SDK의 요청 기반 권한 확인 주기(기본5분)를 유지합니다. 로그인 세션은 최초 로그인부터 최대7일이며 새로고침으로 연장하지 않습니다.

## v0.3 리뷰 수정

`0004_atomic_authority.sql`은 트랜잭션 내 상태 검증용 테이블과 마지막 활성 관리자 보호를 추가합니다. 기존 회원 행은 변경하지 않습니다. 권한·신청·현재 소속은 쓰기와 같은 트랜잭션에서 확인되며 경합은 409로 반환합니다.

최고 관리자가 기존 회원 연결을 승인하면 신청 계정의 Google 로그인과 관리 권한·담당 맹·서비스 소유권을 선택한 기존 회원 ID로 함께 이전합니다. 기존 회원의 UID와 이용 제한 검사는 유지합니다.

개발자는 새 서비스 등록 시 입장 조건을 지정할 수 있습니다. 등록 후 조건 변경은 최고 관리자만 가능합니다. 개발자는 기존 조건을 유지하면서 서비스 주소·이름·로그인 디자인을 변경합니다.
