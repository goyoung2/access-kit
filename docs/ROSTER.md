# 명부 관리

관리 콘솔 `/console#roster`의 **명부** 메뉴에서 파일·붙여넣기·개별 입력으로 관리합니다. Google 계정을 아직 연결하지 않은 사람도 명부에 먼저 등록할 수 있습니다. CID는 기존 게임 UID와 같은 식별자로 사용하며 문자열로 보관합니다.

## 시즌 이름과 소속 관리

최고 관리자는 **시즌 · 소속** 메뉴(`/console#seasons`)에서 **시즌 추가**, **소속 추가**를 누릅니다. 각 목록에서 이름 수정·삭제가 가능하며 **삭제된 항목** 필터에서 복구할 수 있습니다. 같은 종류의 사용 중인 이름은 중복 등록할 수 없습니다. 삭제된 이름을 다시 사용했다면 기존 항목의 이름을 수정한 뒤 복구합니다.

시즌 이름은 직접 정하며 **준비 중 / 진행 중 / 종료**는 별도 상태입니다. 진행 중인 시즌은 **시즌 종료** 후 삭제합니다. 복구해도 자동으로 시작하지 않습니다. 소속은 맹·모임 등의 실제 이름을 입력합니다.

삭제는 이력과 내부 ID를 보존합니다. 삭제한 항목은 등록·승인·복사·정책 설정에서 제외됩니다. 소속을 삭제하면 해당 소속의 시즌 제한 서비스 접근과 담당 관리자 권한이 중지됩니다. 복구하면 기존 명부·담당 관리 권한·서비스 조건을 다시 사용할 수 있으며 전체 이용 정지는 해제하지 않습니다. 확인 창에 연결 기록과 영향을 표시합니다. 삭제된 소속의 명부 기록은 조회만 가능하며 소속 복구 후 수정합니다.

## 조회와 직접 입력

- 시즌·소속을 선택하고 닉네임 또는 UID로 검색합니다. 등록된 명부 / 삭제된 명부 / 전체 이력으로 나누어 볼 수 있습니다.
- **한 명 추가**에서 권역/서버, 닉네임, UID, 소속 소속을 입력합니다. 같은 권역·UID·시즌의 항목은 하나만 등록됩니다.
- **수정**으로 닉네임과 소속을 변경합니다. Google 계정에 연결되기 전에는 UID·권역도 수정할 수 있습니다. 연결된 UID·권역은 다른 계정으로 바뀌지 않도록 이 편집기에서 고정합니다.
- 이미 승인된 계정과 UID가 일치하면 닉네임과 해당 시즌 소속을 반영합니다. 기존 내부 회원 ID와 전체 이용 정지는 유지합니다.

최고 관리자는 전체 소속, 회원 관리자는 담당 소속만 조회·편집할 수 있습니다. 소속 간 이동은 출발·도착 소속 모두에 관리 권한이 있어야 합니다. 개발자 권한만으로 명부를 읽거나 수정할 수 없습니다. 종료된 시즌은 조회만 가능합니다.

## 파일 또는 표 가져오기

**파일 · 붙여넣기로 가져오기**를 누르고 소속·권역을 확인합니다. JSON/CSV/TSV/TXT 파일을 선택하거나 내용을 붙여넣습니다. 엑셀은 닉네임·UID 두 열을 복사해서 붙여넣을 수 있습니다. `.xlsx` 파일 자체를 읽는 기능은 제공하지 않습니다.

다음 JSON을 지원합니다. 예제 UID는 테스트용입니다.

```json
{"nickname_to_cid":{"예시 회원":"900000001"}}
```

```json
{"records":[{"nickname":"예시 회원","cid":"900000001"}]}
```

배열의 `gameUid`, `game_uid`, `uid`도 인식합니다. 긴 UID가 숫자로 변환되며 손실되지 않도록 JSON 문자열로 입력하세요. 안전한 정수 범위를 넘은 숫자형 UID는 거부합니다.

```text
닉네임	UID
예시 회원	900000001
다른 회원	900000002
```

CSV는 같은 두 열을 쉼표로 구분합니다. 닉네임/UID 또는 nickname/CID 헤더는 생략할 수 있습니다. 따옴표로 감싼 CSV 값도 읽습니다.

1. **미리보기**에서 신규·수정·변경 없음·충돌·행별 오류를 확인합니다. 이 단계는 DB를 변경하지 않습니다.
2. 내용을 고치거나 소속·권역을 바꾸면 미리보기를 다시 실행합니다.
3. **확인**을 눌러 반영합니다. 완료 전에는 진행 상태를 표시하며 성공을 미리 표시하지 않습니다.

같은 UID·닉네임의 중복 입력은 건수를 표시하고 합칩니다. 다른 닉네임이 같은 UID를 사용하거나, 다른 소속·삭제 목록에 이미 등록된 UID는 충돌로 표시합니다. 삭제된 항목은 먼저 별도 복구하고, 소속 이동은 개별 수정에서 처리합니다. 파일에 없는 회원은 자동 삭제하지 않습니다.

한 번에 1~1000명, 파일은 2MB까지 가져올 수 있습니다. 더 큰 명부는 나누어 가져옵니다. 입력 오류·충돌이 있으면 일부만 저장하지 않습니다. 미리보기 이후 다른 관리자가 변경했으면 다시 확인하도록 알리고, 반영 중 충돌해도 트랜잭션 전체를 취소합니다.

## 삭제와 복구

**삭제**는 해당 시즌 명부에서 제외하고 연결된 시즌 소속을 해제합니다. 삭제된 명부 필터에서 **복구**할 수 있습니다. Google 계정·내부 회원 ID·다른 시즌·승인 이력은 삭제하지 않으며 전체 이용 정지를 해제하지 않습니다.

승인 회원 공통 서비스의 자격은 별도입니다. 모든 회원 서비스의 이용을 막아야 한다면 기존 **회원 → 정지** 기능을 사용합니다. 시즌 제한 서비스의 변경은 기존 요청 기반 권한 확인 주기(기본 최대 5분) 뒤 반영됩니다.

## 가입 승인·시즌 명부 복사

명부 등록 자체는 Google 계정의 본인 확인이나 회원 승인을 대신하지 않습니다. 사용자가 로그인하고 UID로 신청하면 관리자가 명부와 대조하여 승인합니다. 명부에 있는 시즌·소속은 승인 창의 기본값으로 사용합니다. 삭제된 항목을 실수로 재승인하거나 다른 소속으로 승인하는 것은 서버에서 막습니다.

**시즌 · 소속 → 진행 중인 시즌에서 복사**는 로그인 미연결 명부도 복사합니다. 복사 확인 창에 원본·대상 시즌 이름을 표시합니다. 삭제된 소속은 복사하지 않으며 대상 시즌에 이미 등록·수정·삭제한 항목과 소속은 보존합니다. 회원 승인은 기존 계정과 내부 ID에 연결됩니다.

## 서버 적용

DB 백업 후 `0006_catalog.sql`까지 적용하고 중앙 서버를 배포해야 이 기능을 사용할 수 있습니다. 0005는 기존 명부를 채우고, 0006은 기존 시즌·소속에 수정 버전과 삭제 상태를 별도 테이블로 추가합니다. 기존 회원·소속의 ID와 상태는 변경하지 않습니다. 기존 가입 승인·시즌 소속 변경도 DB 트리거로 명부에 반영합니다. SDK 교체만으로 DB나 관리자 화면이 변경되지는 않습니다. 원격 마이그레이션·배포는 별도 작업입니다.
