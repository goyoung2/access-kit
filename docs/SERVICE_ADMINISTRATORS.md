# 서비스 공동 관리자

서비스 하나와 연결된 명부를 여러 사람이 자기 Google 계정으로 함께 관리합니다. 소유자는 유지하고 공동 관리자를 추가·해제합니다. 중앙 전체의 최고 관리자 권한을 부여할 필요가 없습니다.

## 콘솔 사용

1. 추가할 사람이 먼저 해당 인증 서버에서 Google 로그인과 닉네임·CID 가입을 완료합니다.
2. `/console` → **연결 서비스** → 해당 서비스의 **관리자 · 명부 관리**를 엽니다.
3. **관리자 추가**에서 상대방의 CID를 입력합니다. 추가된 사람은 자기 계정으로 콘솔에 로그인하면 해당 서비스를 볼 수 있습니다.
4. 같은 화면에서 명부의 한 명 추가·수정·삭제·복구와 JSON/CSV/TSV 파일·붙여넣기 미리보기 가져오기를 수행합니다. 파일에 없는 기존 회원은 자동 삭제하지 않습니다.
5. **관리자 해제**는 해당 서비스의 권한만 회수합니다. 소유자는 이 목록에서 해제할 수 없습니다. 공동 관리자는 다른 공동 관리자를 추가·해제할 수 있습니다.

## 명부 권한

서비스 소유자 본인의 자체 명부는 지정한 공동 관리자들이 함께 관리합니다. 서비스 등록이나 창천 기본 명부 선택만으로 중앙 원본의 조회·수정 권한을 얻지는 않습니다.

중앙 공유 명부를 공동 관리하려면 중앙 최고 관리자가 해당 서비스의 같은 화면에서 **이 서비스에 명부 관리권한 부여**를 실행합니다. 부여 전에는 원본 회원 목록과 편집 기능을 제공하지 않습니다. 권한을 회수하면 관리자들의 원본 조회·수정이 차단됩니다. 다른 소유자의 명부에 연결한 경우에도 같은 명시적 위임이 필요합니다.

동일한 원본 명부를 여러 서비스가 공유하면 명부 변경은 그 원본을 사용하는 서비스에 함께 반영됩니다. 다른 서비스의 설정·관리자 권한을 얻는 것은 아닙니다. 연결 명부를 바꾸거나 연결을 해제하면 이전 원본에 대한 서비스 위임은 제거됩니다.

## 권한 범위

| 가능 | 불가 |
|---|---|
| 담당 서비스의 관리자 추가·해제 | 서비스 소유자 해제 |
| 권한이 있는 연결 명부의 회원 CRUD·가져오기 | 다른 명부의 임의 조회·수정 |
| 담당 서비스 이름·URL·로그인 디자인 변경 | 다른 서비스 조회·설정·관리자 변경 |
| 해당 서비스의 개발자 자격으로 입장 | 전역 역할 부여·전체 회원 정지·새 서비스 생성 |

연결 명부나 입장 정책 변경은 소유자 또는 중앙 최고 관리자가 수행합니다. 전역 개발자 권한이 별도로 있는 사람은 기존 서비스 생성 권한을 유지합니다. 전역 이용 정지는 공동 관리자 자격으로 우회할 수 없습니다.

관리자 해제는 다음 API 요청부터 서버에서 검사합니다. 이미 발급한 소비 사이트 세션의 권한은 기존 요청 기반 기본 5분 lease 경계에서 재확인합니다. 이미 받은 명부 화면이나 데이터 자체를 원격으로 회수하는 기능은 아닙니다.

## 적용 상태

SDK 0.5.0의 독립 서버 템플릿에 이 기능과 `0009_service_administrators.sql`을 포함합니다. 창천 새 인증 서버에서도 제공합니다. 기존 환경 업그레이드는 회원·소유자·명부 ID를 보존하며 0009 적용 후 인증 서버를 갱신합니다. 소비 사이트의 기존 SDK 0.4.0 게이트도 서버에서 확인한 서비스 개발자 자격과 호환됩니다. npm 설치만으로 다른 운영자의 서버나 DB가 변경되지는 않습니다.
