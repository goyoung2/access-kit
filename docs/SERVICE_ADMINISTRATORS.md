# 서비스 공동 관리자

서비스 하나와 연결된 명부를 여러 사람이 자기 Google 계정으로 함께 관리합니다. 소유자는 유지하고 공동 관리자를 추가·해제합니다. 중앙 전체의 최고 관리자 권한을 부여할 필요가 없습니다.

SDK 0.6.1부터 기본 명부의 유효한 회원은 **별도 개발자 승인 없이** 설치 스튜디오에서 자기 서비스를 등록합니다. 등록자는 그 서비스의 소유자입니다. 이 자격은 공유 명부의 조회·수정을 허용하지 않습니다. 기존 이용 정지와 명시적인 서비스 등록 권한 회수는 유지됩니다.

## 가입 전 권한 지정

최고 관리자는 `/console#roles` → **가입 전 권한 예약**에서 CID와 역할을 미리 지정합니다. 서비스 등록 허용(방문자 예외), 회원 관리자와 담당 소속, 최고 관리자, 서비스 공동 관리자와 담당 서비스를 선택할 수 있습니다. 서비스 관리자는 해당 서비스의 **관리자 · 명부 관리 → 가입 전 관리자 예약**에서 그 서비스의 공동 관리자만 예약할 수 있습니다.

생성한 일회용 링크를 당사자에게 전달합니다. 링크는 7일 동안 한 번만 사용하며, DB에는 해시만 저장합니다. 당사자가 Google 로그인·닉네임/CID 가입 후 링크의 **로그인·가입 후 권한 받기**를 눌러야 적용됩니다. **예약 CID로 가입하는 것만으로는 관리 권한이 생기지 않습니다.** CID가 다르면 수락할 수 없고, 초대한 관리자의 해당 권한이 해제되거나 예약이 취소·만료되면 수락할 수 없습니다.

같은 예약 화면에서 수락 대기·수락 완료·취소·만료 상태를 확인하고 대기 중인 예약을 취소합니다. 이미 수락한 권한은 기존 계정 권한 설정이나 서비스 관리자 목록에서 해제합니다. 예약만으로 공유 명부 관리권한이 부여되지는 않습니다.

예약은 100건씩 조회하고 **더 불러오기**로 이전 기록을 계속 확인합니다. 오래된 미사용 초대도 이 목록에서 취소할 수 있습니다. 신규 예약이 추가되어도 다음 페이지에 중복되거나 누락되지 않도록 생성 시각과 ID를 함께 사용합니다. 구형 개발자 초대도 수락 시 발급자의 현재 최고 관리자 권한과 수신자의 활성·정지 상태를 같은 트랜잭션 안에서 검사합니다.

최고 관리자가 가입 신청의 Google 로그인을 기존 회원 ID에 연결하면 서비스 소유권·자체 명부 소유권·공동 관리자 지정과 유효한 미수락 초대의 발급 권한을 함께 이전합니다. 명부·서비스 ID와 이미 처리된 초대 이력은 유지하며, 어느 쪽 계정에든 명시된 서비스 등록 권한 회수가 있으면 해제하지 않습니다.

## 콘솔 사용

1. 추가할 사람이 먼저 해당 인증 서버에서 Google 로그인과 닉네임·CID 가입을 완료합니다.
2. `/console` → **연결 서비스** → 해당 서비스의 **관리자 · 명부 관리**를 엽니다.
3. **관리자 추가**에서 상대방의 CID를 입력합니다. 추가된 사람은 자기 계정으로 콘솔에 로그인하면 해당 서비스를 볼 수 있습니다.
4. 같은 화면에서 명부의 한 명 추가·수정·삭제·복구와 JSON/CSV/TSV 파일·붙여넣기 미리보기 가져오기를 수행합니다. 파일에 없는 기존 회원은 자동 삭제하지 않습니다.
5. **관리자 해제**는 해당 서비스의 권한만 회수합니다. 소유자는 이 목록에서 해제할 수 없습니다. 공동 관리자는 다른 공동 관리자를 추가·해제할 수 있습니다.

## 명부 권한

서비스 소유자 본인의 자체 명부는 지정한 공동 관리자들이 함께 관리합니다. 서비스 등록이나 창천 기본 명부 선택만으로 중앙 원본의 조회·수정 권한을 얻지는 않습니다.

중앙 공유 명부를 공동 관리하려면 중앙 최고 관리자가 해당 서비스의 같은 화면에서 **이 서비스에 명부 관리권한 부여**를 실행합니다. 부여 전에는 원본 회원 목록과 편집 기능을 제공하지 않습니다. 권한을 회수하면 관리자들의 원본 조회·수정이 차단됩니다. 다른 소유자의 명부에 연결한 경우에도 같은 명시적 위임이 필요합니다.

동일한 원본 명부를 여러 서비스가 공유하면 명부 변경은 그 원본을 사용하는 서비스에 함께 반영됩니다. 다른 서비스의 설정·관리자 권한을 얻는 것은 아닙니다. 연결 명부를 바꾸거나 연결을 해제하면 이전 원본에 대한 서비스 위임은 제거됩니다.

## 권한 범위

| 가능 | 불가 |
|---|---|
| 담당 서비스의 관리자 추가·해제 | 서비스 소유자 해제 |
| 권한이 있는 연결 명부의 회원 CRUD·가져오기 | 다른 명부의 임의 조회·수정 |
| 담당 서비스 이름·URL·로그인 디자인 변경 | 다른 서비스 조회·설정·관리자 변경 |
| 해당 서비스의 개발자 자격으로 입장 | 전역 역할 부여·전체 회원 정지·새 서비스 생성 |

연결 명부나 입장 정책 변경은 소유자 또는 중앙 최고 관리자가 수행합니다. 전역 개발자 권한이 별도로 있는 사람은 기존 서비스 생성 권한을 유지합니다. 전역 이용 정지는 공동 관리자 자격으로 우회할 수 없습니다.

관리자 해제는 다음 API 요청부터 서버에서 검사합니다. 이미 발급한 소비 사이트 세션의 권한은 기존 요청 기반 기본 5분 lease 경계에서 재확인합니다. 이미 받은 명부 화면이나 데이터 자체를 원격으로 회수하는 기능은 아닙니다.

## 적용 상태

회원 자동 서비스 등록과 가입 전 권한 예약은 `0010_member_services_and_reservations.sql`까지 순서대로 적용하고 서버를 갱신해야 합니다. 다른 맹의 독립 운영에도 자기 환경의 기본 명부를 기준으로 같은 흐름을 제공합니다. 창천 서버의 승인을 받을 필요가 없습니다.

0.6.1의 예약 페이지 조회 인덱스는 `0011_permission_reservation_pagination.sql`로 추가합니다. 기존 회원·명부·권한 행을 변경하지 않습니다.

SDK 0.6.1의 독립 서버 템플릿에 이 기능과 `0009_service_administrators.sql`을 포함합니다. 창천 새 인증 서버에서도 제공합니다. 기존 환경 업그레이드는 회원·소유자·명부 ID를 보존하며 0009 적용 후 인증 서버를 갱신합니다. 소비 사이트의 기존 SDK 0.4.0 게이트도 서버에서 확인한 서비스 개발자 자격과 호환됩니다. npm 설치만으로 다른 운영자의 서버나 DB가 변경되지는 않습니다.
